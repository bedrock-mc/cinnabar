# Server camera packets

The table records the identified vanilla contracts implemented by the camera
packet family. Coverage and remaining owner limitations are tracked separately;
this work does not close full visual or hardware parity. See [FOV](camera-fov.md)
and [third-person placement](third-person-camera.md).

## Vanilla rules

| Area | Vanilla rule | Coverage |
| --- | --- | --- |
| Preset IDs and inheritance | IDs index the current server registry. Child fields override parents; named native parents still contribute inherited fields. Missing parents and cycles do not select a camera. | Inheritance/unknown/cycle/long-chain regression tests. |
| Set values | Omitted position and rotation keep earlier instruction overrides for that preset; explicit fields win over inherited defaults. Facing wins over a simultaneous rotation. | Per-preset state and regression tests. |
| Facing | Distances below 0.01 blocks retain the previous direction; a nearly vertical target retains yaw. | Coincident, vertical and horizontal facing tests. |
| Default and offset reset | `default=true` removes instruction position/rotation. It preserves offset overrides unless `remove_ignore_starting_values` is also true; that flag alone does nothing. | Defaults and offset reset matrix tests. |
| Offsets | Entity offset X changes sign before rotation about the subject's yaw. View offset uses horizontal right and world up. Offset options require an offset-capable rig; the free rig does not support them. | Inherited/explicit offsets and invalid free offsets tests. |
| Native radii | Third-person rigs default to 4 blocks; follow-orbit and fixed-boom rigs default to 10. | Existing third-person and offset tests. |
| Target center offset | Rotate the center offset around the target entity's yaw before adding it to the target position; vertical and coincident directions retain undefined axes. | Actor-yaw offset regression test. |
| Combined options | Packet options produce set, target, remove-target, clear, fade, FOV, spline, attach, then detach events. A later remove or clear wins over an earlier option in the same packet. | Combined-option precedence test. |
| Separate effects | Clear releases the selected server camera and custom FOV while stored spline clocks continue; fade and shake remain separately controlled. | Clear/independent effect tests. |
| Legacy camera packet | The legacy camera/entity IDs trigger education camera photography rather than a view-camera switch. | Counted unsupported photography; no pose mutation. Photography output is unimplemented. |
| Easing selectors | The 32 selectors are linear, spring, then in/out/in-out variants of quad, cubic, quart, quint, sine, exponential, circular, bounce, back and elastic. Unknown selectors use linear. | Selector names/endpoints and representative curve goldens. |
| Spring | Clamp progress to 0..1; use the native sine lookup, cubic wave phase, power-2.2 damping and variable envelope. | Half-progress golden. |
| Sine and elastic | Sine-based curves use the shared trigonometric lookup. Elastic has a 0.3 period for all variants, including in-out. | Golden easing samples. |
| Exponential endpoints | Exponential curves retain their small endpoint residuals: 1/1024 for in/out, 1/2048 for in-out. | Exact endpoint regression tests. |
| Fade default and minimum | Missing times use 1 s in, 0.5 s hold and 1 s out. Extend hold so the total is at least 0.5 s. Negative or non-finite times are invalid. | Default/minimum/invalid tests. |
| Fade overlap | Overlapping fades retain the active color and current alpha, adding keyframes only when extending or raising the envelope. Keyframe comparisons use 0.0001 s tolerance. | Overlap/color continuity tests. |
| FOV | Server FOV is clamped to 30..110 degrees; easing and clear are independent of camera pose. | Bound, ease and release tests. |
| Spline types | Inline type 0 is Catmull-Rom; type 1 is linear. Named registry types are case-insensitive `catmullrom` and `linear`. | Protocol and curve tests. |
| Spline preparation | Native builders require at least 3 linear points and 4 Catmull-Rom points. Segment knots use normalized accumulated straight-edge distance. Catmull-Rom uses half-edge endpoint tangents and half-neighbour interior tangents. | Unequal-distance linear and curved position goldens. |
| Spline tracks | Progress and Euler rotation tracks use their own keyframe times and the easing on the starting keyframe. The final value holds. Euler angles interpolate numerically, preserving full turns. | Independent rotation/full-turn/progress-ease tests. |
| Spline rotation axes | Spline rotations are direct Euler angles in degrees, composed as Y then X then Z quaternion factors. Zero faces −Z; positive X turns the view upward. Unlike set rotations, no pitch negation or 180-degree yaw conversion applies. | Coordinate axes and combined Euler-order tests. |
| Spline duration | Evaluate at exact duration; an update beyond duration ends playback and releases the animated pose to stationary instruction/default values. | Endpoint/overshoot regression tests. |
| Spline registry and interruption | Named playback looks up the most recent registry. Commands prepare all stationary free cameras, and playback advances while they are inactive. Set easing blends from the current pose toward the moving spline sample; clear releases camera selection without stopping the stored clock. | Named/missing lookup, set ease, inactive playback, clear/reselection and expiry tests. |
| Invalid spline data | Unknown names, unsupported kinds, degenerate paths, empty or unordered/non-finite tracks are skipped and counted without destroying a valid current pose. | Protocol admission and runtime invalid-track tests. |
| Shake queues | Positive finite shakes append to independent positional/rotational queues. Active intensities add and clamp to 4. Prior intensity decays at 1 unit/s when the active sum drops. Timers expire after intensity evaluation. Both queues empty removes the effect immediately; stop clears both. | Queue/overlap/decay/stop/invalid regression tests. |
| Shake noise | Use three independently shuffled 2D simplex fields, twelve gradients and fourth-power attenuation. The currently available pack witness uses frequency 10, amplitude 5 degrees and noise multiplier 4; the pinned pack values still need confirmation. Sample at (elapsed×4, 10), then multiply by radians(5)×4×intensity. Translation is world-space; rotational shake subtracts raw pitch/yaw radians and resets roll. | Noise goldens, argument/unit/sign/roll/world-axis regressions and allocation test. |
| Frame work | Preparing curves, tracks, fade envelopes and queue growth occurs during commands. Sampling camera pose, spline, FOV, fade and shake allocates nothing. | Thread-local allocator assertions over 1,000 complete evaluations; no timing assertions. |
| Target speed and reacquisition | A positive rotation speed limits angular motion in degrees per second. Snap applies on acquisition; a new in-range acquisition can snap again. Without continuing targeting, an out-of-range target returns toward the initial orientation. | Angular speed, snap/reacquisition, return and continuation regression tests. |
| Target limits | Default target range is 50 blocks; the wire field named `block_listening_radius` overrides this target distance. Horizontal limits bound yaw relative to the initial orientation; vertical limits map 0..180 degrees to −90..90. A target beyond 1,024 blocks is released. | Asymmetric yaw, pitch, exact range and far-target tests. |
| Missing and removed target | A missing target can resolve later. Once acquired, disappearance removes targeting while preserving its last rotation. Explicit remove-target also preserves that direction as the instruction rotation. | Missing/acquired/removal and subsequent set tests. |
| Orbit collision | Trace eight rays from corners offset by ±0.1 blocks. Shorten to hit distance from the pivot minus the 0.025 near-plane distance, with 0.25 minimum avoidance distance. Stationary free cameras do not shorten. | Wall, corner, ceiling/floor, thin-between-rays, minimum distance, zero allocation tests. |
| Follow-orbit input | Follow-orbit consumes routed yaw/pitch input. Repeated set on the active preset preserves the direction; activation after switching presets or clear starts from the player look. Fixed boom retains its instructed direction. Yaw limits are in native yaw degrees with missing ends defaulting to ±180 degrees. | Input routing, preset direction persistence, partial yaw limits tests. |
| First-person capabilities | The selected first-person rig renders first-person objects regardless of local perspective. Free, fixed, follow and third-person rigs hide them; clear restores the local choice. | All six bases and clear regression test; animated and CPU hand publication covered by a draw-level regression. |
| Local body | Free and orbit cameras render the local player model independently of the saved perspective; first-person cameras hide it. Clear restores the local choice. | Body-publication regression preserves the subject eye and feet. |
| Listener | An omitted or camera listener follows the final rendered camera; player listener follows the player's eye pose. | Inherited selection/clear tests and audio adapter coverage. |
| Starting angles | Custom boom presets apply explicit starting rotation, or inherited base starting angles only when opted in. The starting rotation and opt-in flag belong to the selected preset and are not inherited from custom parents. Fixed-boom starts at zero angles when suppressed; follow-orbit starts from player look. | Explicit/opt-in/suppression/non-inheritance/reactivation tests. |
| Inactive targeting | Target commands prepare all stationary free cameras. Inactive targets continue updating; remove-target only affects the selected camera. Clear removes the active target, preserving its last instruction direction; inactive targets continue. | Two-preset progression, clear, active removal and zero-allocation regression. |
| Player effects | A true player-effects field adds player-state rendering to free cameras. False does not remove capabilities built into other base rigs. Blindness/darkness fog and night-vision lightmaps obey this capability without resetting effect clocks. | Camera capability and vision-publication regression tests. |
| Experimental control camera | The packaged control-scheme camera declares follow-orbit inheritance and camera-relative controls; it uses the same registry inheritance as custom presets. | Definition-shaped inheritance/input test. |
| Native preset restrictions | Native preset names reject radius, starting rotation and yaw-limit overrides. Custom inherited names can use those fields. | Ignored-option count and unchanged pose/input regression. |
| Portal capability | Free cameras have no portal-distortion component, independently of player-effects settings. Clearing the server camera restores the local projection distortion. | Actual projection suppression/restoration regression; exact-version pack component witness remains open. |
| Gameplay FOV capability | Free cameras retain the configured FOV but ignore gameplay zoom and widening. The underlying modifier still advances, and clear restores it. Server FOV instructions remain authoritative. | Actual projection regression with sprint, free selection and clear. |
| Aim command | Clear disables the current request immediately. Set accepts an empty priority preset or an existing named preset. An unknown named preset leaves the previous command intact. | Regression test. |
| Aim registries | Set replaces both category and preset tables. Add retains unrelated names and replaces matching definitions. Packet order is preserved. Level-owned policies survive dimension changes; cached targets are invalidated. | Regression test. |
| Held item | Empty hands use hand settings. An explicit held-item mapping wins over the default-item category. Liquid targeting requires the held item in its preset list and the cached eye outside primary liquid. | Category and liquid query regression tests. |
| Actor priorities | Local actor metadata 136 and 137 select preset and category; target metadata 138 selects actor. Missing or differently typed values use zero. Priority packets update individual triples without restarting the search cycle. Candidate exclusion is sampled on the odd tick; weights read the latest table on the even tick. Registry add/set also preserves the running cycle. A priority of -2 for category zero excludes non-player actors from every category of the preset; players bypass that exclusion. Missing priority entries are zero. | Regression test. |
| Actor admission | Native mobs, boats and minecarts enter the search. Live players in spectator mode are excluded, including players bound to a spectator world default; legacy viewer modes remain distinct. Advertised custom actors use their native base class, or generic mob when the base is absent or unknown. The first definition wins. Unadvertised custom classes are skipped and counted. | Native and custom registry regression tests. |
| Selection bounds | Full vertical/horizontal view angles define a frustum. Admission uses the nearest point of an actor's box and a strict distance bound. Actor centers and exposed block-face centers provide aim points. | Regression test; native mob/boat/minecart eligibility covered; additional hitboxes remain incomplete. |
| Ranking | Priority weight is clamp(1.1 - 0.01 × priority, 0.1, 1.1). Distance scores squared weighted distance. Angle scores weight × (-0.6981316804885864 × dot³ - 0.8726646304130554 × dot + π/2). The lower score wins; equality keeps the earlier candidate. | Golden tests. |
| Occlusion | World geometry excludes hidden candidates. Distance mode also excludes actors hidden behind another candidate box; angle mode omits that actor-box occlusion pass. | Implemented; full native obstruction parity remains incomplete. |
| Tick cadence | Odd ticks cache local player eye/look, category and actor candidates, clear block candidates, and sample the upper half of the far rectangle. Even ticks append lower-half block samples and publish a result. Odd ticks retain the prior result unless its actor disappears or dies. An actor selected on an even tick must still have an owner; a removed winner clears the result. | Two-tick and repeated-frame regression tests; all unseen retained physics ticks are consumed in order, using tick eye height and raw look. |
| Liquid picking | Liquid outlines are full unit cubes regardless of fluid height. Extra layers are checked before primary layers when liquid targeting is enabled. Flowing primary liquids obstruct rays but cannot become targets; extra liquids retain targetability. | Regression and zero-allocation tests. |
| Block ray geometry | Sampling clips cell cubes and retains block outlines; visibility clips outlines. The origin cell always tests its primary outline and is ignored when the ray starts inside it. Integer distance bounds cell steps; equal boundary crossings choose Z, then Y, then X. | Regression and zero-allocation tests. |
| Block sampling | Rays traverse far-plane samples spaced one block apart. Each half contains ceil(half-height) rows and 2 × ceil(half-width) columns. Duplicate intercepted boxes share candidate storage. | Implemented with bounded reusable storage. |
| Input devices | The target result updates a separate interaction direction. This path has no keyboard/mouse exclusion and does not add continuous look input. The active input mode selects the game-mode pick range; the touch setting can select the controller pick range. | Shared evaluator for all devices; downstream reach remains authoritative, native touch reach remap remains incomplete. |
| Action rotation | The camera/control-scheme matrix allows action-triggered player rotation for free and fixed-boom cameras under all five schemes, and follow-orbit under camera-relative or player-relative. Ordinary first/third-person cameras do not rotate the player by this rule. | Matrix and cached-eye regression tests; attack/release adapters use the cached interaction direction to update player facing and the same unsent movement tick. |
| Camera activation | Camera preset activation sends the selected camera preset identifier to the server. First-person perspective is unsupported; other perspectives and cameras without a perspective component are supported. Unsupported cameras or absent aim options send clear with the support flag. Authoritative aim settings arrive separately. | Implemented acknowledgment; no locally invented fallback settings. |
| Leniency and work | Unknown preset commands are counted; unavailable collision evidence suppresses only affected candidates. Per-frame candidate evaluation reuses storage and performs no heap allocations. Finite requests exceeding the bounded block sampling budget are skipped and counted. | Full evaluation allocation test; workload bound is a defensive implementation limit. |
| Highlight | A selected target renders a one-block-wide textured quad at its aim point. Block quads follow the selected face; top/bottom quads orient to the player's dominant horizontal look direction, preserving earlier directions at ties. Actor quads billboard to the displayed camera, including roll. | Geometry and allocation regression tests. |
| Highlight art | The installed pack supplies `textures/ui/aimassist_block_highlight` and `textures/ui/aimassist_entity_highlight`; server packs override them. Visible highlight pixels retain texture alpha; occluded pixels multiply it by 0.5. Both retain white tint. Missing optional art suppresses drawing. | Worker preparation, dependency, draw count and unchanged GPU upload tests. |
| Debug flag | Normal target highlights do not depend on `show_debug_render`. The release client creates candidate debug text when requested but does not submit that text for rendering. | Current release behavior inspected. |
| Highlight pipeline | Two passes use source-alpha/inverse-source-alpha blending, RGB-only writes and no depth write. Occluded pixels use strict greater native depth, visible pixels strict less; reversed depth swaps those comparisons. Native constant bias -33, zero slope and clamp becomes +33 in reversed depth. Both variants are prepared before a target appears. | Two-draw, pipeline and unchanged-work regression tests; exact sampler defaults remain provisional. |
| Camera collision work | Each corner ray walks only the cells it crosses (plus the shape halo) and stops past its first hit, so cost is linear in boom length; known palette shapes and paired door geometry are visited without allocating; unknown IDs and unloaded cells are skipped and counted. | Borrowed visitor regression with allocation counter; per-frame cell bound for a 100-block easing boom; volume-scan equivalence; existing wall and bounds tests. |
| Block tags | Server definitions carry tags in `blockTags`; valid entries survive odd entries, with skips counted. Native door/gate/trapdoor classes carry `one_way_collidable`. | Both runtime ID spaces and session reset tested; remaining native tag families are incomplete. |
| Block ranking | Explicit and matching tag priorities compete by maximum value. With no explicit entry, a tag must exceed −1 to replace the default. Exact and matching-tag exclusions suppress targets. | Priority/exclusion and streamed-tag regressions. |

## Local verification

Build the developer-control client through the shared build-slot limiter, launch
through `tools/cinnabar-mcp` with `headless: true`, and connect with `local_server`.
Pass `-camera-test` to the local server to enable these fixture commands:

- `/cameratest spline`: named Catmull-Rom path with independent progress and rotation.
- `/cameratest inline`: the same path carried directly by the instruction.
- `/cameratest aim`: categories, a preset, actor priorities and a nearby target.
- `/cameratest clear`: release both systems and remove the target.

The developer `state` response reports semantic skips, camera state, aim target
and visibility-query counts. Captures belong outside git. A headless smoke test
establishes packet flow and rendered output; it does not establish matching-version
native visual parity, physical input-device acceptance or hardware frame budgets.

## Remaining limits

See the camera entry in [the parity plan](../../plan.md). In particular, animated
attachment anchors, additional actor hitboxes, complete native block tags,
equal-score actor iteration, the touch pick-range option and fire-resistance
lava fog depend on missing owner data or behavior. Some packaged camera defaults and highlight sampler behavior still
need a pinned-version witness. Catch-up ticks use retained local poses with the
latest admitted remote geometry. Oversized block sampling is bounded to 4,096 rays.
