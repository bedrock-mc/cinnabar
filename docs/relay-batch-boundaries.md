# Relay batch boundaries

The core relays each inbound Bedrock network batch as one outbound batch, as Lunar does (its ADR 0008): server-authoritative anticheats read batch timing, so a handling stall must not move later packets of a client tick into another batch. Both legs set `EnableBatchReading` and `FlushRate = -1`, so gophertunnel's 20 Hz ticker never cuts a batch. A per-direction `packetReader` (core/proxy/proxy.go) owns every flush of its destination: it returns one source batch, the pump forwards each packet's received bytes with buffered `WritePacketRaw` (decoding only the chat Text it rewrites and the Transfer it records), and the reader flushes once after the last packet. While it waits for the next batch it flushes every 1/20 s for packets written outside a forwarded batch. Nothing on a packet path calls `Flush`, `WritePacketImmediate` or `WritePacketDirect`; the final relayed Disconnect is the one exception, written and flushed immediately. Boundaries are kept, not content: an out-of-batch write may join the batch being forwarded. Resource-pack chunks are never relayed after the lossless startup handoff (packs are acquired and served before it), so no batch ends early for them.

The Rust client forms those batches as vanilla does: everything a frame queues leaves as one batch when the frame's update ends (`NetworkHandle::flush_frame`), written by a task that never waits on inbound decoding.
